# Развертывание Zamer CAD на постоянном домене

Эта схема подходит для срочной закрытой beta и первого реального замера. Приложение, API и авторизация работают на одном HTTPS-домене. Данные лежат в отдельном постоянном Docker volume и не удаляются при обновлении контейнера.

## Что понадобится

1. Домен или поддомен, например `app.example.com`.
2. Небольшой постоянно работающий VPS с публичным IPv4.
3. Доступ к DNS домена.
4. Git и Docker Compose на сервере.

Cloudflare Quick Tunnel и ноутбук для реальной работы не подходят: ссылка временная, а при выключении компьютера вход и сохранение перестают работать.

## Что готово в срочной версии

- Каждый проект сначала сохраняется локально на телефоне, затем отправляется на сервер.
- Сервер использует атомарную запись, ревизии и хранит до 50 предыдущих версий проекта.
- Конфликт синхронизации не перезаписывает чертеж: сервер создает отдельную восстановленную копию.
- Удаленный через интерфейс проект переносится в серверную корзину, а не уничтожается сразу.
- DXF R12 экспортируется в миллиметрах: линии, стены, прямоугольники, окружности, дуги, мебель, текст, выноски и линейные размеры.
- Кириллица в DXF хранится в совместимом ASCII Unicode-представлении.

Угловой размер пока намеренно не попадает в DXF. PDF, DWG и IFC в этой срочной версии не считаются готовым экспортом.

## DNS

Создайте A-запись:

```text
Тип: A
Имя: app
Значение: публичный IPv4 сервера
TTL: Auto
```

Если используется корневой домен, вместо `app` укажите `@`.

## Запуск

На сервере клонируйте репозиторий и перейдите в папку приложения:

```bash
git clone --branch source <URL-репозитория>
cd <папка-репозитория>/prototype
cp .env.example .env
```

Откройте `.env` и замените значение:

```text
DOMAIN=app.example.com
```

Запустите:

```bash
docker compose up -d --build
```

Caddy автоматически получит HTTPS-сертификат. Порты `80` и `443` должны быть открыты в firewall сервера.

Проверка:

```bash
docker compose ps
curl https://app.example.com/api/health
```

Ожидаемый ответ содержит `"ok":true` и `"storage":"ready"`.

## Обновление приложения

```bash
git pull
docker compose up -d --build
```

Volume `zamer_data` не пересоздается, поэтому аккаунты, проекты, серверные версии и восстановительные копии сохраняются между обновлениями.

## Резервная копия

Создайте папку и архив постоянных данных:

```bash
mkdir -p backups
docker run --rm -v zamer_data:/data -v "$PWD/backups:/backup" alpine sh -c 'tar czf /backup/zamer-$(date +%Y-%m-%d-%H%M).tgz -C /data .'
```

Запускайте эту команду ежедневно через cron и храните хотя бы одну копию вне VPS.

## Перед первым замером

1. Откройте домен на телефоне и установите PWA на главный экран.
2. Создайте отдельный аккаунт для реального проекта.
3. Создайте тестовую линию, дождитесь статуса `Сохранено`.
4. Обновите страницу и убедитесь, что линия осталась.
5. Скачайте резервную копию `.zamer`.
6. Экспортируйте тестовый DXF и откройте его в AutoCAD, Archicad или другой целевой программе.

Для массовой публичной регистрации следующим этапом нужно заменить файловое хранилище на PostgreSQL. Для одного объекта и закрытой beta текущая схема с постоянным volume, историей ревизий и ежедневными backup подходит.

Кнопка входа разработчика и расширенная защита публичной авторизации пока оставлены как есть по решению текущего этапа. Поэтому эту сборку следует использовать как закрытую beta, а не открывать для неограниченной публичной регистрации.
