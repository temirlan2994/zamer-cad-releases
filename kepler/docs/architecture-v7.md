# Ядро v7: блоки-генераторы, стены под любым углом, помещения — результат (2026-11-07)

Цель: «Revit как приложение, но помещения — блоки». Эскиз собирается из
блоков-комнат (и шаблонов), под ними — настоящие стены и помещения. Этап 1 —
изолированное ядро `core/v7/` + `core/geom/` с тестами `tests/v7-*.test.mjs`;
к интерфейсу не подключено, старый движок работает как раньше.

## 1. Почему

Текущая архитектура даёт системные глюки:

1. **Две правды.** Блоки-комнаты и ручные стены живут отдельно, между ними —
   переводчики (`core/bound-rooms.js`, `loopToRoom`, движки стен v1 и v2).
2. **Съедание с памятью.** `core/room-eat.js` разрушает форму нижней комнаты и
   запоминает исходную (`eatBase`): результат зависит от порядка действий
   (см. `restoreEaten` — десятки строк, чтобы угадать, вернуть ли форму).
3. **Сжатая прямоугольная сетка** (`core/walls-v2.js`, `core/ortho-grid.js`):
   косые и дуговые стены невозможны.
4. **Каждый жест написан отдельно** и сам поддерживает инварианты.

## 2. Принцип: хранится только то, что нарисовал пользователь

| Истина (хранится, `kepler-plan/7`) | Производное (`derive`, не хранится) |
|---|---|
| `levels[]`: высота, отметка | — |
| `blocks[]`: номинальная форма (rect / poly [+holes]), x, y, rotation 0/90/180/270, z, parentId, тип, имя, стиль стен (`walls.exterior/partition`, `edges[i]`) | видимая форма блока (`carved`), стены блоков |
| `walls[]`: ось from→to (любой угол), толщина, justify, base/top, тип, hidden, roomBounding | тела стен со стыками L/T/X и вырезами проёмов, общий контур |
| `openings[]`: host `{wallId, t}` или `{blockId, edge, offset}`, размеры, открывание | стена-носитель, положение, «сироты» |
| `seeds[]`: точка + имя/тип помещения по стенам | помещения: полигоны с дырками, брутто/нетто, источник |
| `pairs['a|b']`: толщина/скрытость общей стены пары блоков | общие перегородки |
| `items[]`, `building`, `site`, `settings`, `variants` (как в v6) | — |

Ничего производного в файле нет: ни формы после съедания, ни стен блоков, ни
контуров помещений. Любая операция меняет только истину; **результат зависит
только от итогового состояния** (путь-независимость — главный тест).

## 3. Сущности

- **Блок** — генератор помещения. Номинальная форма хранится всегда целиком;
  из неё derive строит стены и пол. Порядок «кто выше» — `(z, id)`, от порядка
  массива не зависит; жест «тронул» = `raiseBlock` (z = max+1). Вложенный
  блок (`parentId`) всегда выше родителя. Открытые площадки (терраса, балкон)
  стен не строят; шахты не едят и не съедаются (как `eatablePair`).
- **Стена** — ось-отрезок в осях дома, `justify` как в v6 (какая грань на
  оси; «лево» = `(d.y, −d.x)` при оси Y вниз). Стены блоков — те же записи
  (`source: 'block'`), поэтому весь код тел/стыков общий.
- **Проём** — на стене (`{wallId, t}`, t от `from`) или на ребре блока
  (`{blockId, edge, offset}` — индекс ребра номинальной формы и смещение
  центра). Проём на блоке едет с блоком; стена-носитель ищется геометрически
  (своя стена ребра, общая перегородка пары, ручная стена, закрывающая ребро).
  Ребро съедено — проём «сирота» в `issues`, данные целы; блок ушёл — проём
  вернулся (памяти нет).
- **Семя** — `{id, x, y, name, type}`: имя/тип области, замкнутой ручными
  стенами. Создаётся при «разобрать на стены» (id = id блока, чтобы id
  помещения не менялся) и (этап 2) инструментом «помещение».
- **Помещение** — результат: ограниченная область свободного пространства.
  Имя/тип — от блока с наибольшим `(z, id)`, чья видимая форма содержит
  внутреннюю точку области; иначе от семени; иначе безымянная пустота
  (`source: null`, двор/карман — в площади не входит).

## 4. Конвейер `derive(project, {levelId})`

```
blocks ──carve──▶ видимые формы ──block-walls──▶ стены блоков ┐
walls ────────────────────────────────────────────────────────┴▶ wall-body: тела, стыки, проёмы
   ▶ U = ∪ тел (roomBounding) ▶ помещения = дыры U минус островки (+ открытые площадки)
   ▶ сопоставление: блок / семя / пустота
```

1. **carve** (`core/v7/carve.js`). Видимая форма = номинальная минус
   (номинальные формы блоков выше + зазор = толщина общей перегородки:
   `pairs[a|b].thickness` → большая из `walls.partition` блоков →
   `settings.partition`). Остаток проходит морфологическое открытие
   (волоски тоньше `EAT_SLIVER` = 250 срезаются). Не получается — форма
   номинальная, причина в `issues`: `whole` / `split` / `small` (нет квадрата
   `EAT_MIN_REMAIN` = 500) / `children` (под верхний попадает вложенный).
   Срабатывает и при «ближе перегородки, но без перекрытия» — нижний
   отодвигается до точного зазора (в v6 такой пары не было — см. §7).
2. **block-walls** (`core/v7/block-walls.js`). Стены стоят снаружи видимой
   формы (форма = чистая площадь, как прямоугольник комнаты v6):
   - встречное ребро другого блока на расстоянии 1…450 мм — **одна общая
     перегородка** по центру зазора, толщина = зазор;
   - участок, закрытый снаружи телом ручной стены, — без стены блока;
   - остальное — своя стена (наружная толщина, `edges[i]` переопределяет).
   Концы у вершин, где соседний участок — общая/ручная стена, тянутся до её
   оси: L/T/X без щелей (сетка 2×2 сходится в одном узле X).
3. **wall-body** (`core/v7/wall-body.js`). Узел = общий конец осей (сетка
   0,5 мм). Концы в узле сортируются по углу; между соседями — пересечение
   соседних граней (миттер; T и X получаются сами). Почти коллинеарные
   (< 3°), миттер дальше 3·t или за другим концом короткой стены — встык.
   Тело чинится `clean`, проёмы вычитаются прямоугольником поперёк тела.
   Стык «торец в середину другой стены» без узла — через объединение тел.
4. **Помещения**: дыры объединения тел (без проёмов — дверь не сливает
   комнаты) минус островки внутри дыры; щели (< 0,05 м² или 2A/P < 90 мм)
   отбрасываются в `gaps`. Открытая площадка = её видимая форма минус тела
   стен и закрытые помещения. Нетто — минус островки/колонны, брутто — по
   внешнему контуру. Шахта — помещение с `shaft: true`, в `totalArea` не входит.
5. Результат: `{ carved, walls, wallBodies (polygon, cut), outline (видимые
   тела с проёмами), rooms, gaps, openings, issues }`; всё отсортировано по id,
   полигоны канонические — `deepEqual` сравнивает результаты напрямую.
   Кеш: LRU на 32 входа по JSON этажа и толщин из settings. Результат не
   мутировать.

Производительность: 30 блоков / ~160 стен — ~15–40 мс (тест < 100 мс);
шаблоны — 3–5 мс, проект пользователя — ~10 мс.

**Операции** (`core/v7/model.js`): `addBlock`, `moveBlock` (с вложенными и
мебелью `blockId`), `resizeBlock`, `setBlockRotation`, `raiseBlock`,
`removeBlock`, `addWall`, `addOpening`; `explodeBlock` (`core/v7/explode.js`)
— блок → ручные стены той же геометрии + семя; блоки, которые он ел,
получают его вырез в номинальную форму (иначе снова стали бы целыми под
новыми стенами) — это единственная правка номинала не руками, и она — явная
команда. `magnetSnap` (`core/v7/magnet.js`) — для жестов этапа 2: прижим грань
к грани с зазором перегородки / выравнивание граней, X и Y независимо,
вложенный — к внутренним граням родителя; + направляющие.

## 5. Геометрия (`core/geom/`): своё ядро, без вендора

Нужны булевы операции над полигонами с дырками под любым углом.

**Решение: своя реализация** (`clip.js` ~400 строк + `poly.js`), а не
вендоренный `polygon-clipping`:

- вендор нужно скачать (в этой среде — без сети/подтверждения), проверить
  лицензию и ESM-сборку (у `polygon-clipping` ESM-файл тянет `splaytree` и
  `robust-predicates` — пришлось бы склеивать), а при багах — разбираться в
  чужом коде на плавающей точке (у Martinez-подобных реализаций известны
  падения на совпадающих рёбрах — ровно наш случай: общие стены, касания);
- наши входы — мм, округлённые до 0,5 мм: в целых единицах все предикаты
  точные, и простой алгоритм «разбить все рёбра → классифицировать
  под-ребро по числу оборотов → сшить контуры» устойчив без эпсилонов.
  Вырожденные случаи решаются символическим сдвигом точки (середина +
  ε·нормаль + ε²·g), а не допусками: касания сторон, совпадающие рёбра,
  нулевая площадь, бабочки — покрыты тестами;
- выход канонический (порядок контуров и вершин детерминирован) — это
  нужно для проверки путь-независимости через `deepEqual`.

Ограничения: пересечения округляются до сетки 0,5 мм повторными проходами
(snap rounding без «горячих пикселей»; на чертежах домов сходится за 1–2
прохода); ошибка площади повёрнутых фигур ~ периметр × 0,25 мм (5×5 м —
< 0,005 м²). Сложность: разбиение O((n+k) log n), классификация O(n·m)
с полосами по Y. Файлы грузятся в браузере как ES-модули без сборки и
попадают в manifest артефакта сами, когда их импортирует `app.js`
(`scripts/build-artifact.mjs` собирает граф статических импортов; проверено
`moduleGraph('core/v7/derive.js')`).

API: `union, intersection, difference, xor, clean, overlay`; `area,
outerArea, perimeter, bbox, pointInPolygon, interiorPoint, components,
simplify, orientation, transform, buffer (миттер), erode, opening`.

## 6. Миграция `kepler-plan/6` → 7 (`core/v7/migrate.js`)

`fromV6(project, {warnings})`, `fromAny(rawJson)` (v1–v5 → v6 обычным
`projectFromData`, затем v7):

- комната → блок того же id: x/y — начало, rect или poly (outline, Г с
  `notch` → полигон); у съеденной берётся `eatBase.base` (номинал), сама
  `eatBase` не переносится; `z` = индекс в `rooms`, но съевшая
  (`eatBase.by`) всегда выше съеденной (в v6 съеденная не уходила вниз по
  массиву — без этого `eatChain` перевернулся бы);
- `level.walls[]` → `walls` (axis.a/b → from/to); `wallOverrides`:
  `s|a|b` → `pairs['a|b']`, `e|room|side` → `block.edges[i]`, прочие ключи —
  `legacyWallOverrides`;
- проём комнаты (roomId, side, offset) → `host {blockId, edge, offset}`:
  точка ищется на номинальной форме своей комнаты, иначе на ребре другого
  блока в пределах 460 мм (проём на срезе съеденной стоит на общей стене →
  на ребро верхнего, `swingIn` инвертируется); `hingeStart` — относительно
  направления ребра;
- мебель, участок, building, variants — как есть (варианты — v6-данные,
  мигрируются при выборе варианта, этап 4).

Сверка (`tests/v7-migrate.test.mjs`): все фикстуры `wall-fixtures`, v1–v5,
проект пользователя, три шаблона. Сумма площадей совпадает точно
(≤ 0,005 м²) у 37 из 48 этажей; расхождения объяснены в шапке теста:
стены шахт, стены дома на террасе, диагональные углы 250/100,
ручная стена через комнату, пары ближе перегородки.

## 7. Решения при расхождениях брифа с кодом

- **Зазор «ближе перегородки»**: бриф — «минус формы выше с зазором»; v6
  съедал только при перекрытии. Принято буквально: блоки ближе перегородки
  тоже отодвигаются (одна общая стена точной толщины), иначе стены двух
  блоков налезали бы друг на друга.
- **Общая стена при зазоре 100…450**: v6 — только точный зазор, иначе две
  своих стены внахлёст. v7 — одна стена толщиной в зазор (честнее для
  эскиза; толщину видно). Порог 450 = `MAX_SHARED_GAP`.
- **Резчики — номинальные формы верхних**, а не видимые: проще, порядок
  вычисления не важен; разница — только в полосах зазора.
- **Диагональные углы** (наружные 250 в 100 мм по диагонали) — угол
  миттера честно заходит в соседа на 150×150; не обрезаем стены блоков по
  чужим формам, чтобы «разобрать на стены» оставался без потерь.
- **Терраса** теряет площадь под стенами дома, стоящими на ней (v6 — нет).
- **Шахта** имеет свои стены (v6 вычитал только саму шахту).
- **`explodeBlock`** «запекает» вырез в блоки, которые разбираемый ел, и
  получает дыры в номинале (`shape.holes`) — иначе нельзя разобрать
  вложенный санузел.
- Уровни остались вложенными (`levels[].blocks/walls/…`), как в v6.

## 8. Что переиспользуется из walls-v2

- Модель ручной стены (ось, `justify` = грань на оси, `base/top`,
  `typeId/wallType`, `hidden` = линия разделения, `roomBounding`) — один в
  один, только `axis.a/b` → `from/to`.
- Проём-хост `{wallId, t}` — как есть; + новый хост на ребре блока.
- Идея «одна общая стена пары с толщиной из пары» (`sharedWallThickness`) →
  `pairGap`; пороги `EAT_MIN_REMAIN`, `EAT_SLIVER`, `MAX_SHARED_GAP`.
- Причины несъедаемости (`whole/split/small/children`) и тексты норм
  (`eatFailText`) — для этапа 2.
- Не переиспользуется: сжатая сетка (`ortho-grid.js`), `wallJoinPatches`,
  `bound-rooms.js`, `eatBase/restoreEaten`, движок v1.

## 9. Этапы 2–5

**Этап 2 — интерфейс на v7** (основной объём):
- `ui/app.js`: состояние — проект v7; открытие файла → `fromAny`; сохранение
  `kepler-plan/7` (старые копии приложения не откроют — нужна версия-мост
  или экспорт v6 «для старых», решение пользователя).
- Жесты блоков: перенос/растяжение/поворот/вставка шаблона = операции
  `model.js` + `raiseBlock`; во время жеста — `derive` на каждом кадре
  (кеш, 5–40 мс) — съедание видно на лету, без «конца жеста»; магнит —
  `magnetSnap` с направляющими.
- Стены: рисование под любым углом (привязки — угол 15°/45°, концы к узлам
  и граням), правка концов/толщины/justify; «Разобрать на стены».
- Помещения по стенам: инструмент «семя»; список помещений и ТЭП из
  `derive.rooms`. Нормы: `issues` (overlap с причиной, opening-orphan).
- Нужна правка существующих `core/*.js` (делается здесь, не на этапе 1):
  `core/issues.js`/`norms.js` читать `derive.issues`; `core/tep.js`,
  `schedule.js` — `derive.rooms`; `core/rooms.js` (связность по дверям)
  — по `derive.openings` + помещениям; `core/model.js` — `SCHEMA` 7 и
  `migrate.js` MIGRATIONS[6] = `fromV6`.

**Этап 3 — рендер/3D/экспорт**: `render.js` рисует `outline` (тела с
проёмами), `rooms` (заливка, подписи `label`), `carved`; 3D
(`mesh3d.js`) экструдирует `wallBodies[].cut` по `base/top` (подоконник и
перемычки — по проёмам); DXF/IFC/PDF — из тех же полигонов (полилинии с
дырками, IfcWall по оси + профилю, IfcSpace по помещению).

**Этап 4 — миграция файлов**: автосохранения/облако/IndexedDB открываются
через `fromAny`, сохраняются v7; варианты (`variants`) мигрируются при
выборе; ревизия IFC (`scripts/check-ifc.py`) на v7.

**Этап 5 — удаление старого движка**: `walls-v2.js`, `ortho-grid.js`,
`bound-rooms.js`, `room-eat.js`, `wall-manual.js`, части `walls.js`/`rooms.js`
/`room-shape.js` и их тесты; `settings.wallsEngine`.

## 10. Вопросы к пользователю перед этапом 2

1. Сохранять сразу в `kepler-plan/7` (старые копии не откроют) или первое
   время писать и v6 для совместимости?
2. Общая стена при зазоре 100…450 мм — одна толстая (как сейчас в v7) или
   две своих внахлёст (как v6)?
3. Блоки ближе перегородки — отодвигать (v7) или оставлять как есть?
4. Площадь террасы — минус стены дома на ней (v7) или без вычета (v6)?
5. Магнит: по умолчанию включён в жестах? радиус 300 мм устраивает?
6. Поворот блоков пока 0/90/180/270 — нужен ли произвольный угол блока
   (ядро уже умеет, ограничение только в `setBlockRotation`)?
