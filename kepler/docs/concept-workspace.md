# Концепция дома: работа с проектом

Кнопка **«Концепция»** в верхней панели открывает общий маршрут: исходные данные, варианты, конструкции, применимые правила, бюджет, согласование и передача. Следующий шаг выбирается по состоянию проекта; неизвестные данные показываются отдельно от обнаруженных ошибок. Обычный редактор плана и 3D остаётся основным местом изменения геометрии.

## Варианты

Создайте именованный вариант. При первом ответвлении сохраняется и исходный дом. У вариантов отдельные этажи, комнаты, проёмы, массы, кровли, виды, листы, конструктивные решения, расценки и привязки задания. Участок и общее задание семьи остаются общими. Перед переключением сохраняется уходящий вариант. Сравнение показывает площадь, помещения, окна, доступность и предварительную стоимость. «Выбрать» фиксирует решение по варианту; активный вариант удалять нельзя. Поддерживается до 20 вариантов в проекте.

## Отметки и конструкции

В свойствах этажа можно включить перенос верхних отметок при изменении нижнего этажа. Связанные лестницы пересчитывают подъём, фасадные элементы сохраняют хозяина. Некорректные отметки отклоняются целиком; операция не создаёт частичного состояния в истории. Undo/Redo доступны в редакторе и окне концепции.

В «Конструкциях» укажите систему, состав наружной стены, грунты, источник ограничений и инженера. Сумма слоёв применяется к геометрии только по отдельному флажку. Проверяются связи, расхождения толщины, введённый предельный пролёт и геометрический просвет над лестницей. Это проверка концепции: армирование, несущая способность, узлы и расчёт основания требуют инженерного проекта.

## Бюджет

Введите регион, валюту, дату и источник расценок. Объёмы берутся из текущей модели; цены задаёт пользователь. Отсутствующая цена или недоступный объём не считаются нулём. Нулевая введённая цена допустима. Диапазон −10/+25% по умолчанию — изменяемое допущение, а не статистическая точность. Лимит заказчика оценивается только при полном наборе данных. CSV содержит объёмы, цены, происхождение и допущения. Изменение расценок меняет снимок согласования.

## Правила

«Эскизные ориентиры» и справочный СП 55 не подтверждают соответствие местным нормам. Для Кыргызстана нет автоматически подтверждённого набора порогов. Пользовательский профиль требует регион, документ, редакцию, источник, область применения и указание специалиста, подтвердившего применимость. Вводите пороги явно. Основные комнатные проверки учитывают выбранный профиль; неизвестный профиль не становится положительным результатом. Инсоляция и геометрические проверки имеют собственную область расчёта.

## Согласование

1. Создайте неизменяемый снимок. Его SHA-256 связывает геометрию, задание и параметры концепции с решением.
2. Скачайте клиентский HTML либо создайте облачную ссылку. HTML включает модель, просмотр 3D, прогулку, бюджет и форму ответа; клиент не может изменить исходный проект. При загрузке проверяется целостность.
3. Клиент отмечает место, пишет замечание или решение. Для согласования нужно отдельное подтверждение. Файловый ответ передают автору и загружают в журнал. Имя в таком ответе заявлено участником; это не электронная подпись.
4. При облачном ответе участник входит через Google. Ответы получает владелец ссылки. Ссылка содержит случайный 256-битный адрес, действует 7 дней и может быть отозвана. Отзыв не удаляет уже скачанные копии.
5. Любое изменение содержимого снимка снимает согласование текущего состояния. Прежнее решение остаётся в журнале. Undo может вернуть согласованное состояние.

В проекте хранятся последние 10 полных снимков и до 500 ссылок на контрольные суммы прежних снимков для приёма старых ответов. Журнал ограничен 500 ответами; облачных ссылок — 100. Сохраняйте исходный проект и переданные клиенту файлы для архива.

## Передача

«Скачать комплект» выполняет проверку связей и собирает ZIP: исходный `.kepler.json`, JSON Revit, IFC, DXF, экспликацию, бюджет и `manifest.json` с размерами и SHA-256 файлов. Ошибки связей и пустая модель блокируют выдачу; неполные инженерные данные остаются заметными в манифесте.

Надстройка Revit обновляет только элементы со своими метками исходного проекта, поддерживает отдельный импорт копии и сохраняет отчёт. Стены, проёмы, помещения, уровни и колонны передаются нативно, остальная поддержанная геометрия — DirectShape. Эти элементы не становятся автоматически расчётными конструкциями, семействами мебели или редактируемой нативной лестницей. См. [инструкцию Revit](../revit/README.md).

## Облачное развёртывание и проверки

Новая коллекция `conceptReviews` отделена от личных проектов. До включения ссылок нужно развернуть проверенные правила из корневого `firestore.rules` вместе с новой страницей `review.html`. Компиляция и серверные тесты правил не публикуют их. Команда dry-run:

```sh
firebase deploy --project kepler-plan --only firestore:rules --dry-run
```

Полный интеграционный тест прав выполняется на Firestore Emulator и включён отдельной задачей CI (`firebase.review-test.json`, демонстрационный проект без рабочих данных):

```sh
FIRESTORE_EMULATOR_HOST=127.0.0.1:8184 KEPLER_FIREBASE_TEST_ROOT=/path/to/firebase-test-deps node --test tests/integration/review-sharing.emulator.mjs
```

Для зависимостей теста нужны `firebase-tools`, `firebase`, `@firebase/rules-unit-testing`. Ограниченный серверный тест без документов и развёртывания: `tests/integration/review-rules.remote.mjs`; ему нужны авторизация Firebase CLI и `KEPLER_FIREBASE_TEST_ROOT`. Файловый сценарий согласования работает независимо от развёртывания облачных правил.
