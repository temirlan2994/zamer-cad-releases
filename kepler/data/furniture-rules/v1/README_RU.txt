Версия 1.0.0 • 14 ноября 2026

487 правил / 31 раздел / 20 сценариев / 48 приемочных спецификаций.
48 уникальных веб-источников и 5 приложенных планов. Один местный нормативный источник является указателем на документ: полный актуальный текст не импортирован.

С ЧЕГО НАЧАТЬ

1. Для чтения всей базы: FURNITURE_RULES_RU.txt.
2. Для подключения к AI-модулю: START_PROMPT_RU.txt + FURNITURE_RULES_RU.json + PROFILES_RU.json.
3. Для разработки геометрического движка: INTEGRATION_RU.txt + EVALUATORS_RU.json + три *.schema.json.
4. Для задания конкретного дома: заполнить BRIEF_TEMPLATE_RU.json, связать геометрию по project_input.schema.json и активировать нужные SCENARIO_LIBRARY_RU.json.
5. Для будущей приемки движка: ACCEPTANCE_CASES_RU.json.

КАК ЧИТАТЬ ПРАВИЛО

id — постоянный идентификатор.
category — область.
requirement — что нужно получить.
applies_when — когда проверять.
severity — hard, conditional_hard или soft.
basis — происхождение требования.
parameters — размер, единица, границы измерения, роль числа.
check — спецификация проверки, не исполняемый код.
exceptions — исключения.
source_ids — ссылки на реестр первичных источников.
related_rule_ids — связанные записи, в том числе чтобы не учитывать одну метрику дважды.
missing_data_result — unknown.

ПРАВИЛА ИНТЕРПРЕТАЦИИ

Кровать у стены, одинаковые тумбы, обязательный остров, телевизор в каждой гостиной и фиксированный процент заполнения не являются универсальными требованиями.
Удобство выбирается для конкретной семьи. Физические ограничения и применимые требования безопасности не компенсируются красотой.
Число без границ измерения неоднозначно. Отступ от края стола уже включает сидящего; это не чистый проход за спинкой.
Проверяется реальное использование: человек сидит, стул отодвинут, шкаф открыт, диван разложен, посудомойка работает.
Пересечение зон не всегда ошибка: различаются твердые тела, движение, действия и предпочтения; временная совместимость учитывается отдельно.
Состояния pass/fail/unknown/not_applicable не взаимозаменяемы. Неизвестная модель оборудования не отключает ее проверку безопасности.
Зарубежные рекомендации не объявлены обязательными нормами Кыргызстана. ADA по умолчанию выключен; местный нормативный профиль ожидает подтверждения.

ЧТО ПРОВЕРЕНО В ЭТОМ ПАКЕТЕ

Синтаксис JSON, уникальность 487 ID, ссылки правил на источники, связи сценариев, согласованность числа записей, три JSON Schema и два синтетических примера. Результат — в PACKAGE_VALIDATION.json.
validate_package.py проверяет пакет данных. Он не запускает оптимизацию и не подтверждает эргономику конкретного дома. Для полной проверки JSON Schema используется необязательная библиотека jsonschema; без нее скрипт явно сообщает пропуск этой части.

ЧТО ЯВЛЯЕТСЯ ЗАДАНИЕМ ДЛЯ РАЗРАБОТКИ

Реализация 23 типов проверяющих модулей, импорт/калибровка планов, каталог реальных изделий, поиск вариантов, сценарная симуляция и независимый геометрический контроль.
48 приемочных случаев еще не выполнялись на будущем движке. Исходный пример спальни синтетический; его координаты показывают формат, а не проверенное решение приложенной планировки.

ПРИНЦИП ОЦЕНКИ

Сначала обязательная допустимость, затем удобство и композиция. Сравнивать несколько различных решений по одинаковым метрикам. Для заявления о превосходстве над человеком нужны независимые одинаковые задания, профессиональное слепое сравнение и опыт реальных пользователей; внутренний балл программы этого не доказывает.
